接上五六个 MCP 服务器后，往往立刻多出五六十个工具。如果全量把工具 Schema 塞进系统提示词，不仅第一轮对话就吃掉上万 Token，模型还经常因为“菜单太长”挑错工具；让模型一个接口接一个接口往返调用，查 20 条记录就要来回 20 轮模型请求。

Mizar 用两套协同机制解决这两个痛点：**按需搜索（`tool_search`）** 与 **沙箱编排（`codemode`）**。

## 对比传统模式 vs Mizar 模式

假设你需要“找出本周报错最多的 5 个接口，并拉取它们最近一条链路详情”：

- **传统模式**：50 个工具 Schema 全部预加载；模型先调 `list_endpoints`，等返回结果后再逐一发起 5 次 `get_trace`，耗时且消耗大量输入上下文。
- **Mizar 沙箱编排**：模型在一段轻量隔离 JS 脚本里一次性循环调完外部工具、在沙箱内排序过滤，只把最终整理好的 5 行摘要返回给对话窗口。

```javascript title="模型在 Codemode 沙箱中实际编排的脚本示例"
const items = await tools.mcp__metrics__list_endpoints({ window: "7d" });
const top5 = items.sort((a, b) => b.errors - a.errors).slice(0, 5);

const details = [];
for (const ep of top5) {
  const trace = await tools.mcp__trace__get_latest({ endpoint: ep.name });
  details.push({ endpoint: ep.name, errors: ep.errors, status: trace.status });
}

return details;
```

## `tool_search`：延迟工具按需检出

当你把不常用的大型服务标记为 `"exposure": "deferred"` 时，这些工具在首轮对模型不可见。Mizar 会在发现存在延迟工具时自动启用 `tool_search`（默认开关为 `toolSearch.autoEnable: true`）：

1. 模型在确实需要查 Jira、Grafana 或数据库时，传入自然语言关键词调 `tool_search`；
2. 检索引擎基于名称、描述和参数结构进行关键词排序，默认最多返回 `8` 条（可通过 `toolSearch.defaultLimit` 调整）完整工具定义；
3. 被命中的工具随后即可在当前链路中直接参与调用或进入编排。

## `codemode`：隔离 JS 沙箱与内置边界

Codemode 运行在内嵌的轻量 JavaScript 运行时中，**专为胶水逻辑与批量调用设计，不是通用 Node.js 环境**。

### 沙箱内有哪些能力

- `await tools.<name>(args)`：直接以异步函数调用当前可用的工具（包括默认挂载的 MCP 工具）。
- `ALL_TOOLS`、`await searchTools(query)`、`await describeTool(name)`、`await describeNamespace(prefix)`：允许脚本在运行期自省并动态发现沙箱内工具签名。
- `store(key, value)` / `load(key)`：在同一会话的多次 `codemode` 调用间持久化共享中间结果，避免把几十 KB 原始 JSON 传出沙箱再二次输入模型。
- `console.log` / `info` / `warn` / `error`、`text(str)`、`exit()` 与标准 `return`。

### 沙箱刻意不提供什么

为了确保模型生成并立即执行的编排脚本绝对可控，沙箱内**没有文件系统 API（`fs`）、没有 `fetch` 或任意网络 Socket、没有定时器，也没有 Node 全局变量**。脚本唯一能触达的外部世界，就是你在工具栏或 `mcp.json` 中授权放行的具名工具。

同时运行时带硬性资源熔断：单 Worker 最大 **256 MiB** 内存、**1 MiB** 调用栈，最多并行 **2** 个沙箱 Worker，默认单次执行 **120,000 ms**（2 分钟）超时。极慢的批量任务可在脚本首行声明注解覆盖超时（支持范围 `100` ~ `600000` ms）：

```javascript title="按单次脚本定制超时时间"
// @options: {"timeoutMs": 300000}
const rows = await tools.mcp__warehouse__export_summary({ days: 30 });
return { count: rows.length };
```

## 按项目需求调配开关

可以在 `~/.mizar/settings.json` 或 `<workspace>/.mizar/settings.json` 中调整两者的协同行为：

```json title="settings.json 中的编排与搜索配置"
{
  "toolSearch": {
    "autoEnable": true,
    "defaultLimit": 8
  },
  "codemode": {
    "autoEnable": true,
    "onlyMode": false,
    "inlineBudget": 3000,
    "timeoutMs": 120000
  }
}
```

- `codemode.autoEnable`：默认 `true`——一旦系统里注册了受沙箱管理的工具（例如默认暴露档位的 MCP），自动向模型提供 `codemode` 工具。
- `codemode.onlyMode`：设为 `true` 时，几乎所有直接工具声明都会收口为通过 `codemode` 调度，只保留 `codemode`（以及启用了 `deferred` 工具时的 `tool_search`）站在最前方，把首轮 Tool Schema 占用压到极致。
- `codemode.inlineBudget`：默认 `3000` Token。只要所有沙箱工具拼接出的类型声明不超过此预算，就会直接内联进 `codemode` 描述；超过预算时改为先提示可用命名空间，让模型按需调用 `describeNamespace()` 查看。

<Callout type="tip">
  如果你在调试 MCP 工具时想看模型究竟传了什么参，可以先把该工具在 <code>.mizar/mcp.json</code> 中临时改为 <code>"direct"</code> 观察几轮，确认顺畅后再切回默认 <code>codemode</code> 节省 Token。
</Callout>
