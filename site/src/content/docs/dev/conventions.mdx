## 模块组织与依赖约束

- **禁止使用 `mod.rs`**：模块组织一律采用现代 Rust 风格 `src/foo.rs` + `src/foo/bar.rs`。生产模块用 `use crate::xxx`，单元测试块内统一 `use super::*;`。
- **文档与参考仓边界**：每个 crate 顶部都应具备中文 `//!` 模块说明，并标明对应的原生参考路径（现有少数历史例外如 `mizar-llm-http`）。`references/` 目录已被 `.gitignore` 排除，仅供对照设计原型，**切勿 `git add`**。
- **Workspace 依赖管理**：根 `Cargo.toml` 不含 `[package]`；所有版本声明集中在 `[workspace.dependencies]`，子 crate 清单一律写 `{ workspace = true }` 并启用 `[lints] workspace = true`。
- **错误处理与锁惯例**：公共错误类型使用 `thiserror` 并统一接入 `cordis::BoxError`，不引入 `anyhow`。代码库中 `.lock().unwrap()` 为既定可接受模式，无需特地包一层或替换为 `parking_lot`。

## 双语文案契约（不要统一成单语！）

工具说明与终端文本在不同消费者之间有严格语言分工，切勿为了“风格统一”全部改成中文或全部改成英文：

| 位置 | 语言要求 | 原因 |
| :--- | :--- | :--- |
| `//!` 模块注释与行内注释 | 中文 | 对齐架构设计文档与原生参考映射 |
| 工具 `description` 与参数 Schema 描述 | **英文** | 直接注入模型上下文，改成中文会实测降低工具调用准确率 |
| 工具运行期校验错误（如缺参数） | 中文（如 `"缺少 path 参数"`） | 返回给人阅读排障的直观反馈 |
| TUI 界面文案与 Commit Message | 中文或英文均可 | 按清晰准确优先 |

## `pi-emphasis` 双向契约与跨 Crate 联改

- **UI 双向约定**：`crates/mizar-tui-ui/src/emphasis.rs` 中的 `reply_guidance_prompt()` 负责生成给模型的标注格式提示文本，同文件内的渲染器消费这些标记做终端强调渲染。**改生成端必须同步改渲染器，并让配对单测同时断言两端**。
- **跨 crate 公共类型联动**：`mizar-tui-ui` 中的 `OverlayKind`、`OverlayAction` 与 `UiEvent` 在 `mizar-tui` 内有大量构造与模式匹配点；改其中一个枚举或字段，必须跑完整 `cargo check --workspace`，不要只 check 单个包。

## Feature 门控与测试规范

`mizar-agent-spine` 定义了六个可裁剪 feature：`legacy`、`coding`、`compaction`、`sqlite`、`trajectory` 与 `router`。任何来自可选依赖的 `use` 语句都必须配上精确的 `#[cfg(feature = "...")]`，否则裁剪特性时编译立刻中断。

```bash title="必须验证的最小 feature 门控与测试规范"
# 验证全部可选 feature 关闭时依然能过编
cargo check -p mizar-agent-spine --no-default-features
```

编写测试时注意三条具体约定：

1. **无 `tempfile` 依赖**：仓库不引入 `tempfile` crate，临时目录测试请使用 `std::env::temp_dir().join(format!("mizar_xxx_{}", std::process::id()))` 并记得收尾清理。
2. **集成测试显式注册**：`mizar-agent-spine` 的集成测试通过 `tests/integration/main.rs` 按 `#[cfg(feature)]` 汇总挂载，新增加集成测试模块时必须同步添加到 `main.rs`。
3. **对齐测试编号与零跳过**：`crates/cordis/tests/compat.rs` 采用连续 `compat_NN_<描述>` 对齐 TS 原版测试用例。所有新增行为必须配备退化即失败（fail on regression）的确定性断言，禁止用 `#[ignore]` 或重试掩盖并发时序问题。

## 标准 CI 检查与 Commit 规范

<Callout type="important" title="Verified 字段只写本轮实际跑过的结果">
  提交信息的 <code>Verified:</code> 段只允许列出你在<strong>最后一次改代码之后</strong>亲眼跑过且全绿的真实命令输出；不添加 AI 署名，跨 crate 修改按 crate 分组简要说明设计意图（Why），不复述代码 Diff。
</Callout>

```text title="标准 Commit Message 模板"
feat(scope,scope): 一句话概括核心改动

- 阐明原因与设计取舍，按 crate 分组说明。

Verified:
- cargo clippy --workspace --all-targets -- -D warnings: passed (0 warnings).
- cargo test --workspace: passed (0 failed).
```
