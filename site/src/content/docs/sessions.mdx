Mizar 将每轮用户提示、模型输出、工具参数与返回结果都记录为只追加事件流（`SessionEvent`），并在此之上构建了断点恢复、树形分叉、无损压缩、静态情景回溯与三泳道性能剖析五套能力。

## SQLite WAL 持久化与可靠性

- **单写者线程隔离（`mizar-session-sqlite`）**：默认落盘于 `~/.mizar/sessions.sqlite`（可通过 `MIZAR_SESSION_DB` 或 `settings.json` 中的 `sessionDb` 覆写；传入 `none` / `off` 或 CLI `--no-persist` 则退化为纯内存会话）。开启 WAL 模式与 `busy_timeout = 5s`，由独立的 Single-Writer 后台线程以最多每事务 `128` 条事件批量刷盘，不阻塞 Tokio 异步调度器；只读查询均使用 `query_only`。
- **`SQLITE_BUSY` 瞬时错误上报**：当多进程并发争抢库锁且重试耗尽时，写者线程会通过 `pending_transient_error` 向上游显式报告持久化警告而非静默丢日志。
- **恢复与防丢挂起修复**：使用 `-c` / `--continue` 自动续接当前工作区最近会话，或 `-r` / `--resume [id]` 指定历史会话。若上次进程异常崩溃导致最后一条 `tool_call` 缺少对应的 `tool_result`，恢复重放与 `/tree` 分叉都会自动补齐自愈占位记录，防止严格校验协议报错。

## `/tree` 树形分叉与自动标题

- **`/tree` 分叉**：在任意历史序列点 `seq` 执行 `fork(id, up_to_seq)`，会在同一事务内复制前缀事件并记录 `parent_id` 与 `fork_seq`。你可以安全尝试另一条重构方案，原始主线历史丝毫无损。
- **后台标题生成（`mizar-session-title`）**：首轮用户输入及每间隔 `20` 轮会异步总结 `MMDD｜TYPE｜Topic` 格式标题（如 `FIX`、`FEA`、`DOC`）；一旦通过 `/rename <title>` 手动命名（标记 `TitleSource::Manual`），后台自动更新会尊重人工标题不再覆盖；无参执行 `/rename` 则立即触发模型重生成。

## 上下文压缩（Compaction B-5）与缓存感知尾部剪枝

当长对话逼近模型上下文窗口上限时，Mizar 通过**两道渐进机制**保住准确率与 KV Cache 命中率：

1. **缓存感知尾部剪枝（`mizar-compaction/src/pruning.rs`）**：每步送审前先对**非历史前缀的尾部区间**执行确定性剪枝：
   - **`compaction.supersedeReads`（默认 `true`）**：当同一文件路径随后已被完整重新 `read` 覆盖时，安全裁掉早先的旧 `read` 返回文本。
   - **`compaction.dropUseless`（默认 `true`）**：清理已被后续操作覆盖或确认无效的零命中检索噪声输出（始终保护 `skill` 加载结果不被裁）。
   - **8k 热尾保护与 90 分钟冷缓存清仓**：剪枝永远保留最近 **`8,000` Token 热尾前缀不动**（仅在闲置超过 `90` 分钟冷缓存后才允许清仓），同时通过向事件流追加轻量 `SessionEvent::ToolResultPrune` 标记实现，因此**既有 Prompt 前缀字节完全一致**，不会反复打断服务端的 Prompt Cache。
2. **检查点摘要压缩（`mizar-compaction` B-5 体系）**：
   - 当估算使用量跨过 `effective_window * triggerRatio`（默认 `triggerRatio = 0.80`，可通过 `compaction.maxContextTokens` 设定人为上限，保留最近 `keepRecentTokens = 20000` Token 原文）时自动触发压缩，也可随时运行 `/compact [focus]` 手动触发。
   - **B-5 精确校准与护栏**：
     - 锚定上轮真实 `TokenUsage::prompt_tokens()` 校准窗口余量，并对未知模型提供安全默认窗口回退，防止误判或漏压。
     - 摘要请求强制将思考强度置为 `ReasoningEffort::Off` 且保持同前缀尾置指令，确保压缩自身稳定不超时。
     - 触发 L3 窗口溢出或隐性连续截断时自动恢复重试。
     - **`FileGuardTracker` 压缩后写护栏**：挂载在 `tools/pre-execute`，如果某文件曾在压缩前被读过但当前工作上下文已丢失其原文，直接用 `write` 整文件覆写会被拦截提示「先 `read` 或改用局部 `edit`」，杜绝盲写毁码。

## 单一静态 `recall` 工具

旧版本拆分双工具并在压缩后才动态挂载的做法会破坏 KV Cache 工具前缀。现在 `mizar-recall` 只注册**唯一一个静态工具 `recall`**，并以 `ToolExposure::Direct` 从首轮起常驻冻结在工具表中：

- **双模式穿透检索**：传入 `query` 时利用 `mizar-session-sqlite` 内置的 Unicode 1..=3 n-gram **FTS5 全文索引**穿透压缩检查点检索历史摘要（`defaultSearchLimit = 8`，`limit` 最大 `20`），无持久化时自动退化为内存扫描；传入 `seq`（可选 `end_seq`、`session_id`、`offset`、`limit`、`to_file`）时分页拉取完整原始事件正文（单次默认上限 `6,000` 字符）。
- **跨分叉作用域校验**：支持检索同一 `lineage` 谱系或工作区会话，并在结果中明确标注 `is_current_session`，超长日志可用 `to_file: true` 直接导出为临时文件供分段读取。

## `/trace` 剖析器与 `--trace-out` 结构化导出

- **交互三泳道剖析器（`Ctrl+T` / `/trace`）**：
  - 顶部 **WaveBand** 全会话脉冲带支持点击跳转到任意轮次。
  - **Timeline** 页签分三道并行展示：**L0 输入与告警**（用户输入、`CTX`、`RepeatToolGuard` 连续重复调用告警）、**L1 模型响应**（TTFT 等待 + 流式 Decode 段）、**L2 工具执行**（包括 `codemode` 内部的嵌套子工具跨度）。支持在 `Duration` / `Seq` / `Actual` 三种时间轴间切换。
  - **Hotspots** 与 **Inspector** 展示各工具耗时排行、单步 Token 详情及完整入参/返回。
- **无头结构化导出（`--trace-out <path>` / `MIZAR_TRACE_OUT`）**：`mizar exec` 运行结束时无论成功、超时或异常退出，都会按命令行优先于环境变量的规则将完整的 `TrajectoryExport` JSON 原子写入目标路径，便于自动化评测与回归流水线采集指标；交互模式也可用 `/export [path]` 导出原始 JSONL 轨迹。
