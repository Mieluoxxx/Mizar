大模型在多步编程循环中主要消耗在**重复读取前缀 Token**。一旦系统提示词里夹杂按秒跳变的时间戳、运行时无故抖动工具 Schema、或者每步重新扫描修改指令文本，服务端 Prompt / KV Cache 就会全量失效重算。Mizar 从提示词、工具表、指令加载到协议线格式四层贯通「**静态前缀稳定**」设计。

## 精简静态英文系统提示词（`mizar-system-prompt`）

系统提示词按 `order` 拼接插件段落（纯英文静态骨架，默认**不含**工程哲学或虚构性格段，仅当 `settings.json` 配置了非空 `personality` 时插入）：

| `order` | 段落 ID | 职责说明 |
| :--- | :--- | :--- |
| `0` | `identity` | `DEFAULT_IDENTITY`（`You are a coding assistant running inside Mizar...` 及随用户语言回复规则） |
| `20` | `personality`（可选） | 仅采用 `settings.json` 中显式配置的非空 `personality`（省略、空串或纯空白均占 `0` 字节） |
| `30` | `tools_guide` | 由 `mizar-tools-coding::build_tools_guide` 按当前会话声明组装 `<tools>` 与去重后的 `<rules>`（含独立并行原则与路径清晰规范） |
| `40` | `runtime_protocol` | `DEFAULT_RUNTIME_PROTOCOL`：说明 `<environment_context>`、`<project_instructions>`、`<system-reminder>`、`<skill_content>` 与 `<mizar-compaction>` |
| 末尾 | `emphasis`（可选） | 仅交互 TUI 且未关闭 `MIZAR_TUI_EMPHASIS_GUIDANCE` 时挂载，约定 `[[Done]]` 等胶囊语法；无头 `exec` 模式下从不注入 |

<Callout type="info" title="Turn-0 顺序、技能注入与压缩刷新">
  发起 Turn 0 前，<code>mizar-agent-loop</code> 通过 <code>EVENT_AGENT_PREPARE_TURN</code> 固定上下文片段装配顺序；若会话声明了 <code>read</code> 或 <code>bash</code>，<code>mizar-skills</code> 会在其间按需注入含 <code>&lt;location&gt;</code> 的 <code>&lt;available_skills&gt;</code> 目录或展开 <code>/&lt;name&gt;</code> 的 <code>&lt;skill_content&gt;</code>。当压缩或上下文溢出重试改变可见历史后，<code>build_for_session(Some(&amp;session.id))</code> 与 <code>tools.list_declared(Some(&amp;session.id))</code> 会按会话同步刷新。
</Callout>

## 启动期静态工作区指令发现（`mizar-instructions`）

`AGENTS.md` / `CLAUDE.md` 的读取策略已从「每步按工作区子目录动态 `stat`」升级为**启动期一次性静态发现并通过 `ctx.effect` 注入 `SystemPrompt`**（`inject: ["systemPrompt"]`）：

- **扫描层级与候选文件名**：
  1. 全局目录：`~/.mizar/`（可由 `MIZAR_HOME` 重定向）与 `~/.agents/`（`MIZAR_AGENTS_HOME`）。
  2. 项目祖先链：从当前工作区目录向上回溯至 `projectRootMarkers`（默认 `[".git"]`）标记的仓库根，按从顶到底顺序读取 `candidates`（默认 `["AGENTS.md", "CLAUDE.md"]`）及本机忽略覆盖文件 `localCandidates`（默认 `["AGENTS.local.md", "CLAUDE.local.md"]`）。
- **去重与超预算淘汰策略**：
  - 同组内对规范化去除空白后的内容计算 SHA-256 去重；内容不同则并存保留。
  - 单文件上限 `instructions.maxSourceBytes`（默认 `1 MiB` = `1,048,576 B`），所有指令总预算 `instructions.maxBytes`（默认 `65,536 B`）。当总字节数超限时，**优先淘汰距离当前工作区最远（最宽泛）的祖先文件**，竭力保住离当前代码最近的目录指令，并在正文按 UTF-8 字符边界安全截断。
- **零运行时 I/O**：指令装配完毕后整个会话生命周期内不再扫描子目录，既消除了每步磁盘 `stat` 抖动，又保证系统提示词前半段永远稳固不变。传入 `--no-instructions` 或设置 `instructions.enabled: false` 可彻底关闭。

## 精简按需的工具声明表

为消除无效前缀占位与中途声明抖动：

- **`MinimalCoding` 默认 4 件套**：默认仅声明 `read`、`bash`、`edit`、`write`，省去独立 `grep`/`find` 与沙箱 Schema 开销。
- **`codemode` 按需稳定激活**：默认休眠；仅在 MCP 静态配置启用 `codemode`、`--tools codemode` 或配置 `codemode.enabled`/`onlyMode` 时于首轮即加入声明，且在后台 MCP 握手前后维持 `codemode` 声明与 `<mcp_servers>` 摘要字节完全一致。
- **零冗余省略**：未配置 MCP Server 时跳过 `tool_search`；已移除独立 `skill` 工具（改由 `<available_skills>` `<location>` 按需读取 `SKILL.md`）。

## 协议线级前缀保序、缓存断点与视觉降级

三大底层协议适配器分别针对主流模型网关的 KV Cache 与视觉能力做了专用对齐（详见 [模型与兼容参数参考](/reference/models/)）：

- **Anthropic Messages（`mizar-llm-messages`）**：
  - 先计算 `prefixDigest` 再注入 `cache_control` 断点（放在 `system`、最后一个 `tools` 条目［受 `supportsCacheControlOnTools` 控制］及最后一条 `user` 消息的末尾内容块；长缓存发送 `ttl: "1h"`），确保切换缓存保留策略不破坏签名 `thinking` / `redacted_thinking` 回放。
  - 工具回执带图片时序列化为 `tool_result.content` 文本 + base64 图像块数组（纯文本保持字符串）。
- **OpenAI Responses（`mizar-llm-responses`）**：
  - 默认 `supportsDeveloperRole: true`、`useTopLevelInstructions: false`（将系统提示词作为 `input[0]` 的 `developer` 消息内联，设为 `false` 时自动降级为 `"system"` 角色）；按 `compat` 开关门控 `store`、`temperature`、`reasoning` 与 `prompt_cache_key`，禁用项绝不出现在请求体中。
  - 保序回放 `outputItems` 消除 `IN_DROP`；工具图片序列化为 `function_call_output.output` 的 `input_text` + `input_image` 数组。
- **OpenAI Chat Completions & DeepSeek（`mizar-llm-completions`）**：
  - 固定前缀配合会话亲和头与 `prompt_cache_key`；并行工具含图时，先按序写出同批全部 `role: "tool"` 回执（带图回执末尾追加 `(see attached image)`），再统一附加一条合成 `role: "user"` 消息按序携带全部图片。
- **非视觉模型统一降级（`supportsImages`）**：当目标模型在目录中声明不支持图片（未知模型默认允许图片）时，三种协议都在序列化前通过 `message_for_model` 将用户与工具图片替换为 `[image omitted: current model does not support image input]`，不发送图片块或合成图片消息。
