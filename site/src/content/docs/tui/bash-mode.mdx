写代码时经常需要一边问 AI、一边自己敲几条命令确认现状：比如顺手瞄一眼 `git status`、快速跑一遍测试，或者确认端口是不是被占着。没必要切出 TUI 再复制报错贴回来——直接在 Mizar 输入框前加一个 `!` 或 `!!` 就够了。

## `!` 与 `!!` 的核心区别

决定前缀用一个还是两个感叹号，只看一个问题：**下一轮你想不想让模型看到这条命令和它的输出？**

```text title="真实混合工作流示例"
!!git status                    # 仅本地速览工作区状态（零 Token、不进上下文）
!cargo test                     # 跑测试，把报错输出顺便留进下一轮模型上下文
为什么刚才第 2 条测试断言失败？     # 模型已经直接看到了上方测试栈信息，立即开修
```

## 视觉线索与无缝切换

在空输入框的第一个字符输入 `!` 后，编辑器会立刻给出清晰的状态线索，防止误把纯本地命令发给模型（或反过来）：

- **输入单个 `!`**：输入框高亮为绿色强调边框，顶部标题明确显示 **`Bash (! · 载入上下文 · Enter 执行 · Esc 退出)`**；命令完成后，消息条目旁带 **`· 已入上下文`** 标记。
- **再多敲一个 `!` 变成 `!!`**：输入框切换为柔和中性边框，顶部标题变为 **`Bash (!! · 不载入上下文 · Enter 执行 · Esc 退出)`**；完成后记录旁带 **`· 仅本地`** 标记。
- **随时退回普通对话**：把前缀感叹号删回空行，或直接按 <kbd>Esc</kbd>，输入框立即恢复常规聊天模式。

<Callout type="note" title="跳过模型审批弹窗">

由于 `!` 和 `!!` 命令是你亲手键入并确认回车的，即使你在本次会话开启了 `--approve`（见 [CLI 参数](/tui/cli/)）或 `/approval ask`（见 [斜杠命令](/tui/commands/)），本地 Bash 模式也不会反过来向你弹一次冗余确认框。

</Callout>

## 中断长任务与大输出落盘保护

- **单路串行防错**：同一时刻只运行一条本地 Bash 命令，防止手滑连敲两条互相冲突的写命令。
- **按 <kbd>Esc</kbd> 干净杀死整棵子进程树**：万一跑了一句 `cargo test` 死循环或者开发服务器忘了加 `--once`，按 <kbd>Esc</kbd> 会向独立的进程组直接发出终止信号，保证连同派生出的所有子进程一并清场，不会留下僵尸进程占着端口或文件锁。
- **2,000 行 / 50 KiB 大输出落盘**：当本地命令吐出上万行构建日志时，对话流内只精简显示末尾核心报错段，同时自动把**完整日志**存进系统临时目录下的 `mizar/mizar-bash-*.log` 并给出路径，方便随时查阅全文。

## 在会话恢复与 `/tree` 分支里的表现

不管是 `!` 还是 `!!`，执行记录都会持久化保存到本地会话数据库 `~/.mizar/sessions.sqlite`（更多会话管理见 [会话、分叉与性能轨迹](/tui/sessions/)）。这意味着：

- 你用 `mizar -c` 或 `mizar --resume` 回来时，此前顺手查过的 `!!git log` 输出依然整整齐齐留在聊天视图里供你回看；
- 但在发送请求给大模型、计算侧边栏 `Context` 占用以及触发长对话压缩时，`!!` 条目会被严格排除在外，既能留作人类备忘，又不浪费一分钱输入上下文。
