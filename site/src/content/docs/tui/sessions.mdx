Mizar 默认会把每轮对话、工具返回和分支节点持久化写入本地单文件数据库 `~/.mizar/sessions.sqlite`（启用单写者 WAL 模式，不卡顿界面渲染也不怕终端意外闪退）。退出 Mizar 时，终端会直接印出精确接续命令，方便随时回到刚才的现场（更多启动选项见 [CLI 参数](/tui/cli/)）：

```bash title="退出后接续与恢复会话"
# 直接恢复当前工作区最近一次会话
mizar -c

# 打开交互列表按时间/轮次挑选任意历史会话
mizar --resume

# 如果在只读容器或一次性演练场景不想留磁盘记录
mizar --no-persist
```

也可以通过环境变量 `MIZAR_SESSION_DB` 调整数据库文件位置，或直接设为 `none` / `off` 全局禁止写盘。想把当前排查历程发给队友复核时，输入 `/export` 即可一键导出（其他会话控制命令见 [斜杠命令](/tui/commands/)）。

## 用 `/tree` 从任意回合分叉探索

遇到“思路 A 改了一半发现架构不顺，想退回第 4 轮换方案 B 重试、但又不舍得直接删掉方案 A”的典型难题，不需要把仓库 reset 掉重开新会话。

在输入框输入 `/tree`：

1. 界面会展开按父子关系组织好的整棵会话树（清晰保留普通对话与 `!` / `!!` 本地 Shell 记录）；
2. 用方向键定位到你想回退的那一个历史节点回车；
3. 从该节点继续提问即生成一条全新的平行分支——两条思路都在历史库里完整共存，想切换回去对比随时再打开 `/tree` 选回原节点即可。

## 上下文压缩（`/compact`）与 FTS5 情景回溯

长会话接近上下文预算时，Mizar 通过 `mizar-compaction`、`mizar-session-sqlite` 与 `mizar-recall` 协同工作，既控制窗口水位又不丢失历史细节：

- **渐进压缩与手动 `/compact [focus]`**：步前先以 L1 零模型批量剪枝大工具输出（保留头尾摘要与回溯句柄）；若仍超过阈值（或执行 `/compact 保留重构决策` 手动触发），生成确定性 `<mizar-digest>` 与检查点摘要（同前缀尾置指令复用 Prompt Cache），溢出或连续截断时自动恢复。
- **压后安全护栏**：压缩后禁止对已存在文件未经重读直接整文件 `write`（始终放行精确局部 `edit`），并对同代次重复 `read` 自动去重。
- **FTS5 无损情景回溯**：SQLite WAL 数据库内建 FTS5 `1..=3` Unicode n-gram 索引（无落盘时自动退回内存扫描）。发生首次剪枝/压缩或处于 `/tree` 分叉谱系中时，延迟工具 `recall_search` 与 `recall_read` 自动向模型激活，支持穿透压缩边界检索并分页读取历史原貌。

## 用 `/trace`（<kbd>Ctrl</kbd>+<kbd>T</kbd>）排查为什么慢

总觉得某次请求等待时间很长，却说不清是首包响应慢、模型推理链路太长，还是某个工具调用卡住了几分钟？按 <kbd>Ctrl</kbd>+<kbd>T</kbd>（或输入 `/trace`）就能打开全屏交互式轨迹分析器。

/>

轨迹分析器把一次次交互铺在同一条毫秒时间轴上，由三块联动区域构成：

- **WaveBand（波段总览）**：快速俯瞰整场会话每一轮的起伏密度，识别哪一轮发生了密集工具风暴。
- **Timeline（并发时序泳道）**：同轴并排展开大模型流式响应、各个并发/串行工具耗时区间，以及异常重试或超时卡点。
- **Hotspots（耗时热点榜）**：按墙钟耗时自动排序，最耗时的调用直接排在最前，一眼看出谁拉高了总延迟。

### 在 `/trace` 视图中的常用操作键

- <kbd>Tab</kbd>：在各面板与列表聚焦区之间循环切换
- <kbd>m</kbd>：切换统计/时序展示视角模式
- <kbd>/</kbd>：输入关键词过滤特定工具名或 Span
- <kbd>Enter</kbd>：展开当前选中 Span 的完整耗时细分与详细元信息
- <kbd>Esc</kbd>：关闭轨迹分析器返回对话

<Callout type="tip">

注意区分 [本地 Bash 模式](/tui/bash-mode/) 中的 `!` 与 `!!`：纯本地的 `!!` 命令不会发起 LLM 请求，自然也不会拖慢模型首包延迟；排查模型吞吐瓶颈时，看 `/trace` 里的模型调用 Span 最为准确。

</Callout>
