先新建一份最简全局配置，告诉 Mizar 你日常习惯使用的模型、推理强度和默认工具范围：

```json title="~/.mizar/settings.json"
{
  "defaultProvider": "deepseek",
  "defaultModel": "deepseek-chat",
  "reasoningEffort": "medium",
  "toolsPreset": "all"
}
```

保存后重新启动 `mizar` 即刻生效。全局配置文件默认存放在 `~/.mizar/settings.json`（可通过环境变量 `MIZAR_HOME` 重定向），而项目专属设置放在仓库根目录下的 `.mizar/settings.json`。

<Callout type="warning" title="严格 JSON 语法：不要写注释或末尾逗号">
  Mizar 解析 <code>settings.json</code>、<code>models.json</code> 与 <code>mcp.json</code> 时仅自动剥离 UTF-8 BOM 头，<strong>不支持</strong> <code>//</code> / <code>/* */</code> 注释，也不容许尾随逗号。文件格式有误会在启动时直接报错中断，避免静默落空引发误操作。
</Callout>

## 四级配置叠加顺序

配置按从低到高的优先级依次叠加，后一级会覆盖前一级同名字段的标量值：

1. **内置默认值**：开箱即用，无配置文件时直接运行。
2. **全局目录 `~/.mizar/`**（或 `$MIZAR_HOME`）：存放个人默认模型、常用凭据与跨项目黑名单。
3. **项目目录 `<workspace>/.mizar/`**：提交到团队仓库，覆盖当前项目的模型偏好、规则路径或 MCP 约束。
4. **环境变量与 CLI 参数**：临时覆盖本次运行行为，如 `--minimal`、`--approve`、`API_KEY`、`MODEL`、`MIZAR_SESSION_DB`。

## 为什么黑名单、技能目录与模块屏蔽采用追加而不是清空

绝大多数字段都是“项目配置直接替换全局配置”，但有三项刻意设计为**跨层级并集追加**：

- `excludeTools`：全局屏蔽列表、项目屏蔽列表与 CLI `--exclude-tools` 参数全部累加生效。假设你个人在 `~/.mizar/settings.json` 禁用了一个高危命令，即使某个开源项目自己的 `.mizar/settings.json` 又屏蔽了 `edit`，你的个人防线依然不会被顺手清空。
- `skills.customDirs`：全局个人技能目录与当前项目指定的团队技能目录会合并扫描，让公共技能与仓库私有技能共存。
- `disabledPlugins`：全局与项目声明禁用的内置可选模块 ID 会合并、排序并去重，同时对核心内核服务实施自保护（不可禁用）。

<Callout type="note">
  所有配置键名均采用 <code>camelCase</code>（例如 <code>defaultProvider</code>）。唯一保留的历史兼容别名是 <code>defaultThinkingLevel</code>，等价于 <code>reasoningEffort</code>。
</Callout>

## 模型与会话基础字段

最常放在全局 `settings.json` 的运行期默认值如下：

```json title="模型与会话偏好"
{
  "defaultProvider": "openai",
  "defaultModel": "gpt-5",
  "reasoningEffort": "high",
  "maxSteps": 40,
  "persona": "回答简练直接，修改前先确认相关测试。",
  "sessionDb": "~/.mizar/sessions.sqlite"
}
```

- `reasoningEffort`：控制推理模型默认思考档位，可选 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。
- `maxSteps`：单轮任务最多连续执行多少步工具调用；设为 `0` 表示不设上限。
- `persona`：附加在默认系统提示词末尾的长期协作风格说明。
- `sessionDb`：自定义会话数据库存储路径；也可以通过环境变量 `MIZAR_SESSION_DB` 设为 `none` 或 `off` 临时关闭磁盘持久化。

## 工具集与工作区边界

如果某类任务只需读写或审计代码，在项目 `.mizar/settings.json` 里收窄工具权限比口头提醒更可靠：

```json title="<workspace>/.mizar/settings.json"
{
  "toolsPreset": "minimal",
  "tools": ["read", "edit", "write", "grep", "find"],
  "excludeTools": ["mcp__prod__*"] ,
  "restrictToWorkspace": true
}
```

- `toolsPreset`：内置三档预设——`all`（完整 6 工具，默认）、`minimal`（仅 `read`/`bash`/`edit`/`write`）、`read-only`（仅 `read`/`grep`/`find`）。
- `tools` / `excludeTools`：分别用于白名单保留和黑名单剔除，均支持 `*` 通配符（如 `mcp__prod__*`）。
- `restrictToWorkspace`：默认为 `false`；改为 `true` 后，文件工具与 `@` 引用都会拦截工作区根目录之外的路径。**注意它不会拦截 `bash` 命令**，完整安全策略请看 [权限与安全](/security/)。

## 按需发现与 Codemode 沙箱

当项目接入较多 MCP 工具时，可以通过这两个模块控制上下文膨胀：

```json title="工具发现与编排开关"
{
  "toolSearch": {
    "autoEnable": true,
    "defaultLimit": 8
  },
  "codemode": {
    "autoEnable": true,
    "onlyMode": false,
    "inlineBudget": 3000,
    "timeoutMs": 120000
  }
}
```

- `toolSearch.autoEnable`（默认 `true`）与 `defaultLimit`（默认 `8`）：存在延迟加载工具时自动注入 `tool_search`，每次最多检出 8 条匹配工具。
- `codemode.autoEnable`（默认 `true`）与 `onlyMode`（默认 `false`）：自动在注册外部/沙箱工具时提供 `codemode` JS 执行器；开启 `onlyMode` 会把所有直接工具收口进沙箱脚本统一调度。
- `codemode.inlineBudget`（默认 `3000` Token）与 `timeoutMs`（默认 `120000` ms）：控制工具类型声明随系统提示词内联时的 Token 上限，以及沙箱单次默认超时时间。

## 项目规则与技能扫描

如果你需要在大型 Monorepo 中调大或收紧 `AGENTS.md` 上下文预算，可以按需覆盖：

```json title="规则与技能目录控制"
{
  "instructions": {
    "enabled": true,
    "candidates": ["AGENTS.md", "CLAUDE.md"],
    "localCandidates": ["AGENTS.local.md", "CLAUDE.local.md"],
    "projectRootMarkers": [".git"],
    "maxBytes": 65536,
    "maxSourceBytes": 1048576,
    "followSubdirs": true
  },
  "skills": {
    "enabled": true,
    "customDirs": ["~/team-skills", ".internal/skills"],
    "catalogDescriptionMaxLength": 500
  }
}
```

- `instructions.maxBytes`（默认 `65536`）限制注入模型的规则总字节数；超过预算时会优先保留离当前目录最近的规则。单个超过 `maxSourceBytes`（默认 1 MiB）的超大文件会自动跳过。
- `followSubdirs`（默认 `true`）允许在读取或编辑深层子目录文件时动态补载该目录的规则文件。
- `skills.enabled` 控制是否启用 `.agents/skills`；`customDirs` 可额外挂载团队公共技能目录。

## 上下文压缩、情景回溯与分身配置

长时间重构与大量工具输出不再只能手动 `/clear` 重来，可通过 `compaction`、`recall`、`sessionTitle` 与 `subagent` 精细调优（详见 [会话、分叉与性能轨迹](/tui/sessions/)）：

```json title="压缩、回溯、标题与 Subagent 配置"
{
  "compaction": {
    "enabled": true,
    "autoCompact": true,
    "defaultContextWindow": 128000,
    "triggerRatio": 0.8,
    "keepRecentTokens": 20000
  },
  "recall": {
    "enabled": true,
    "defaultSearchLimit": 8,
    "readCharLimit": 6000
  },
  "sessionTitle": {
    "enabled": true,
    "thinkingLevel": "low"
  },
  "subagent": {
    "maxSteps": 20,
    "maxStepsCap": 40,
    "timeoutSecs": 180,
    "maxConcurrent": 4,
    "stallTimeoutSecs": 45,
    "maxWatchdogAlerts": 2
  }
}
```

- `compaction`：单阶段检查点压缩。按模型真实可用窗口（`context_window - reserved_output`，可用可选 `maxContextTokens` 封顶）的 `triggerRatio`（默认 `0.8`）触发，生成确定性 `<mizar-digest>` 与摘要并自动从 `ContextOverflow` 恢复；内置压后重复 `read` 去重与写前重读守卫（对已存在且超过 50 行的文件整文件 `write` 需先重读，始终放行 `edit`）。
- `recall`（默认 `enabled: true`、`defaultSearchLimit: 8`、`readCharLimit: 6000`）：静态常驻 `Direct` 单一 `recall` 工具（支持 `search` / `read`），基于 SQLite WAL FTS5 索引穿透压缩与谱系边界无损检索历史记录。
- `sessionTitle` 与 `subagent`：`sessionTitle` 异步生成 `MMDD｜TYPE｜Topic` 会话标题（可设 `model` 覆写 `provider/model`，尊重 `/rename` 人工修改）；`subagent` 控制后台单层常驻分身的步数、并发、超时及零 Token 活性看门狗（`stallTimeoutSecs: 0` 关闭看门狗）。

## 界面偏好、`/settings` 面板与模块启停

在终端内输入 `/settings`（别名 `/config`）即可打开按 **[界面]**、**[运行]**、**[压缩]**、**[模块]** 分组的交互式设置浮层——切换后即时生效，并采用增量原子修补（`patch_settings_file`）写回全局 `~/.mizar/settings.json`，不会破坏手写的其他 JSON 字段：

```json title="界面偏好与可选模块屏蔽"
{
  "disabledPlugins": ["mcp", "tool-search"],
  "ui": {
    "theme": "auto",
    "screenMode": "fullscreen",
    "showThinking": true,
    "verboseExpanded": false,
    "sidePanelOpen": true,
    "mouseCapture": true,
    "approvalMode": "auto"
  }
}
```

- `disabledPlugins`：声明禁用 12 个内置可选模块 ID（`tools-coding`、`tool-search`、`codemode`、`mcp`、`skills`、`instructions`、`compaction`、`recall`、`session-title`、`subagent`、`trajectory`、`repeat-guard`）或 10 个官方宿主/TUI 扩展 ID（`file-mentions`、`local-bash`、`approval-gate`、`tui`、`tui-emphasis`、`tui-side-panel`、`tui-timeline-rail`、`tui-trajectory-view`、`tui-selection`、`tui-clipboard`，其中 `"tui"` 会级联关闭全部 `tui-*` 扩展）。在 `/settings` 的 **[模块]** 分组中可通过轻量原子开关在空闲时无销毁启停（`mcp` 启动禁用时延后到首次启用再初始化；任务运行中自动保护拒绝切换）；`llm`、`sessions`、`tools`、`systemPrompt`、`agentLoop`、`spinePlugins` 受核心自保护，任何配置均不可禁用。
