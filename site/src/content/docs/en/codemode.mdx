Connecting five or six MCP servers often introduces fifty or more tools at once. Stuffing every tool schema into the system prompt consumes tens of thousands of tokens on the very first turn and causes models to mispick tools from an oversized menu; meanwhile, calling endpoints one by one forces twenty separate round-trips just to inspect twenty records.

Mizar solves both problems with two complementary mechanisms: **on-demand search (`tool_search`)** and **sandbox orchestration (`codemode`)**.

## Traditional Mode vs. Mizar Mode

Suppose you ask Mizar to "find the top 5 erroring endpoints this week and fetch the latest trace for each":

- **Traditional mode**: All 50 tool schemas are preloaded; the model calls `list_endpoints`, waits for the response, then makes 5 sequential `get_trace` turns—slow and expensive in input tokens.
- **Mizar sandbox orchestration**: The model runs a single isolated JS script that loops over the external tools, sorts and filters inside the sandbox, and returns only a concise 5-row summary to the conversation.

```javascript title="Example orchestration script run by the model in Codemode"
const items = await tools.mcp__metrics__list_endpoints({ window: "7d" });
const top5 = items.sort((a, b) => b.errors - a.errors).slice(0, 5);

const details = [];
for (const ep of top5) {
  const trace = await tools.mcp__trace__get_latest({ endpoint: ep.name });
  details.push({ endpoint: ep.name, errors: ep.errors, status: trace.status });
}

return details;
```

## `tool_search`: Lazy Loading Deferred Tools

When large or infrequent servers are configured with `"exposure": "deferred"`, their tools remain hidden on the first turn. Mizar automatically enables `tool_search` whenever deferred tools are present (`toolSearch.autoEnable: true` by default):

1. When the model needs Jira, Grafana, or database tools, it calls `tool_search` with natural-language keywords;
2. The search engine ranks candidates by tool name, description, and parameter schema, returning up to `8` full tool definitions by default (configurable via `toolSearch.defaultLimit`);
3. Matched tools become immediately callable—either directly or inside orchestration scripts—for the rest of the session.

## `codemode`: Isolated JS Sandbox & Hard Boundaries

Codemode executes inside an embedded lightweight JavaScript runtime **designed strictly for glue logic and batch tool calls—not a general-purpose Node.js environment**.

### What's Available Inside the Sandbox

- `await tools.<name>(args)`: Call any currently accessible tool (including default-tier MCP tools) as an async function.
- `ALL_TOOLS`, `await searchTools(query)`, `await describeTool(name)`, `await describeNamespace(prefix)`: Introspect and dynamically inspect tool signatures at runtime inside scripts.
- `store(key, value)` / `load(key)`: Persist intermediate values across multiple `codemode` invocations within the same session, avoiding passing tens of kilobytes of raw JSON back through the model prompt.
- `console.log` / `info` / `warn` / `error`, `text(str)`, `exit()`, and standard `return`.

### What the Sandbox Intentionally Excludes

To keep model-generated scripts strictly contained, the sandbox provides **no filesystem API (`fs`), no `fetch` or raw network sockets, no timers, and no Node globals**. The only external capabilities a script can reach are the named tools explicitly authorized in your toolset or `mcp.json`.

The runtime also enforces hard resource circuit breakers: **256 MiB** memory and **1 MiB** call stack per worker, up to **2** concurrent sandbox workers, and a default execution timeout of **120,000 ms** (2 minutes). Slow batch scripts can override the timeout via a first-line annotation (valid range: `100`–`600000` ms):

```javascript title="Override timeout for a single script"
// @options: {"timeoutMs": 300000}
const rows = await tools.mcp__warehouse__export_summary({ days: 30 });
return { count: rows.length };
```

## Tuning Options per Project

You can customize how discovery and sandbox orchestration behave in `~/.mizar/settings.json` or `<workspace>/.mizar/settings.json`:

```json title="Discovery and orchestration settings in settings.json"
{
  "toolSearch": {
    "autoEnable": true,
    "defaultLimit": 8
  },
  "codemode": {
    "autoEnable": true,
    "onlyMode": false,
    "inlineBudget": 3000,
    "timeoutMs": 120000
  }
}
```

- `codemode.autoEnable`: Defaults to `true`—automatically exposes the `codemode` tool whenever sandbox-managed tools (such as default-exposure MCP servers) are registered.
- `codemode.onlyMode`: When `true`, almost all direct tool declarations are funneled through `codemode`, leaving only `codemode` (plus `tool_search` if `deferred` tools exist) at the top level to minimize first-turn schema overhead.
- `codemode.inlineBudget`: Defaults to `3000` tokens. As long as the combined type signatures of sandbox tools fit within this budget, they are inlined directly into the `codemode` tool description; above this budget, Mizar lists available namespaces instead so the model can inspect signatures on demand with `describeNamespace()`.

<Callout type="tip">
  When debugging an MCP tool and you want to see the exact arguments the model passes, temporarily set that tool to <code>"direct"</code> in <code>.mizar/mcp.json</code> for a few turns, then switch back to the default <code>codemode</code> to save tokens.
</Callout>
