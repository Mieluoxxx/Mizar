Mizar is built on **Rust 1.98.0** (edition 2024). The workspace consists of **30 crates** wired together around the custom **`cordis`** microkernel via service injection (`inject` / `provide`) to form the `"stream model call → execute tools → write back to session"` main loop, delivered as a terminal workbench through **`mizar-tui`** (the single binary entry point `mizar`).

The authoritative architecture references in the repository are **`docs/plugins.md`** and **`AGENTS.md`**; this section focuses on architectural boundaries, [hands-on plugin development](/en/dev/cordis/), and [engineering conventions](/en/dev/conventions/).

## Three Zero-Runtime Isolation Boundaries

The following **3 core crates are strictly prohibited from adding** `tokio`, `cordis`, `reqwest`, `rquickjs`, or `rusqlite` dependencies:

- `mizar-tui-ui`: Pure terminal rendering state machine, Markdown highlighting, themes, and `@` / editor interaction logic;
- `mizar-llm-types`: Pure model protocol data structures, message blocks, and capability type contracts;
- `mizar-trajectory-core`: Pure trajectory sampling, three-lane timeline calculation, and hotspot models.

<Callout type="warning" title="It will compile, but the boundary must not be broken">
  Although Cargo technically allows you to add <code>tokio</code> to these three crates, doing so leaks async or I/O side effects into pure state machines and cross-surface data models, breaking snapshot tests and standalone reuse. Any async scheduling, HTTP transport, JS sandbox, or disk persistence must be lifted up into the <code>mizar-tui</code> or <code>mizar-agent-spine</code> host layer.
</Callout>

## Five-Layer Crate Topology Overview

| Layer | Representative Crates | Responsibility Boundary |
| :--- | :--- | :--- |
| **Microkernel** | `cordis` | Fiber state machine, service `provide`/`inject`, `ctx.effect` cleanup, and 5 event dispatch modes |
| **Pure Core** | `mizar-tui-ui` · `mizar-llm-types` · `mizar-trajectory-core` | Zero-runtime pure data/UI state machines supporting fast standalone unit tests and `cargo check` |
| **LLM Protocols & Routing** | `mizar-llm-http` · `mizar-llm-router` · `mizar-llm-{completions,responses,messages,mock}` | Credential expansion, `completions`/`responses`/`messages` protocol adapters, and mock latency simulation |
| **Tools, Extensions, Memory & Storage** | `mizar-tools` · `mizar-tools-coding` · `mizar-mcp` · `mizar-codemode` · `mizar-tool-search` · `mizar-instructions` · `mizar-skills` · `mizar-compaction` · `mizar-recall` · `mizar-session` · `mizar-session-sqlite` | Tool exposure/truncation/serialized write queue, MCP/QuickJS sandbox, instruction & skill discovery, L1–L3 compaction & FTS5 recall, and WAL persistence |
| **Host & Binary Entry** | `mizar-agent-loop` · `mizar-agent-spine` · `mizar-tui` | Main loop orchestration, 30-crate feature-gated assembly (`AgentSpinePlugin` / `spinePlugins` hot toggling), and terminal event host |

## Fast Local Verification Commands

Use sub-second single-crate checks when modifying pure UI logic; whenever you touch cross-crate enums, protocols, or assembly ordering, run full workspace verification (CI requires zero clippy warnings and all tests passing):

```bash title="Common development and CI verification loop"
# Sub-second check while editing UI logic
cargo check -p mizar-tui-ui

# Verify minimal feature combination has no missing cfg gates
cargo check -p mizar-agent-spine --no-default-features

# Full CI checks (exact match with repository requirements)
cargo test --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```
