Mizar is built on **Rust 1.98.0** (edition 2024). The workspace is consolidated into **10 coarse-grained crates** wired deterministically via the static **`mizar-core::spine::MizarRuntime` composition root** and **`mizar-types::hooks` typed hooks / `HookGuard`** into the `"stream model call → execute tools → write back to session"` loop, delivered through **`mizar-tui`** (`mizar` binary) and shared with Merak Desktop via **`mizar-client`**.

The authoritative architecture references in the repository are **`docs/plugins.md`** and **`AGENTS.md`**; this section focuses on isolation boundaries, [hands-on runtime & hooks](/en/dev/runtime/), and [engineering conventions](/en/dev/conventions/).

## Compilation Isolation Boundaries

1. **Pure Core & Pure UI Boundary (2 Crates)**: `mizar-types` and `mizar-tui-ui` are **strictly prohibited from adding** `tokio`, `reqwest`, `rquickjs`, `rusqlite`, or `tracing`:
   - `mizar-types`: Pure core contracts, `hooks` primitives (`HookGuard` / `SyncEventBus` / `WaterfallHook` / `SerialHook`), LLM DTOs, trajectory models, and client algorithms (also **forbids `ratatui`, `crossterm`, and any internal crate**);
   - `mizar-tui-ui`: Pure terminal UI state machine, `TuiFeatures`, `pi-emphasis`, and virtualized Markdown rendering.
2. **Merak Desktop Zero-TUI Boundary**: **`mizar-client` (and `mizar-types`) strictly forbid `ratatui`, `crossterm`, or `mizar-tui-ui`** so desktop hosts embed Mizar with zero terminal dependencies.

<Callout type="warning" title="It will compile, but the boundary must not be broken">
  Although Cargo technically allows adding <code>tokio</code> inside pure core crates, doing so leaks async or I/O side effects into pure state machines and cross-surface models, breaking fast checks and shared reuse. Lift async scheduling, HTTP transport, JS sandboxing, and disk persistence into <code>mizar-core</code>, <code>mizar-client</code>, or <code>mizar-tui</code>.
</Callout>

## Four-Layer 10-Crate Topology Overview

| Layer | Crates | Responsibility Boundary |
| :--- | :--- | :--- |
| **Pure Core (2)** | `mizar-types` · `mizar-tui-ui` | Zero heavy-runtime contracts, `hooks`, trajectory math, and pure UI state machine for sub-second `cargo check` |
| **Base Capabilities (3)** | `mizar-llm` · `mizar-tools` · `mizar-session` | `LlmRuntime` + 3 wire adapters + routing/retry; `ToolRuntime` pipeline + 6 tools + `tool_search`; WAL SQLite, `recall`, and FTS5 |
| **Isolated Extensions (2)** | `mizar-codemode` · `mizar-mcp` | Optional feature-gated `rquickjs` QuickJS sandbox and external stdio/HTTP MCP client |
| **Core & Hosts (3)** | `mizar-core` · `mizar-client` · `mizar-tui` | Domain modules & `MizarRuntime::build` composition root; zero-TUI shared host runtime; CLI / `mizar exec` / terminal adapter |

## Fast Local Verification Commands

Use sub-second single-crate checks when modifying pure UI logic; whenever you touch cross-crate enums, protocols, or assembly ordering, run full workspace verification (CI requires zero clippy warnings and all tests passing):

```bash title="Common development and CI verification loop"
# Sub-second check while editing UI logic
cargo check -p mizar-tui-ui

# Verify minimal feature gates (codemode/mcp disabled), including test targets
cargo check --locked -p mizar-core --no-default-features --all-targets

# Remaining CI checks
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace --no-fail-fast
```
