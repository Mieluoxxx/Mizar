Drop a five-line `AGENTS.md` into your repository root, and Mizar picks up your project conventions on the very next launch:

```markdown title="AGENTS.md"
# Repository Conventions

- Read `docs/architecture.md` before modifying Rust code.
- Run `cargo test --workspace` and verify everything passes before committing.
- Use camelCase for all config keys; never add comments or trailing commas in JSON.
- Write CLI/TUI errors in user-facing wording and tool schemas in English.
```

## Supporting `AGENTS.md`, `CLAUDE.md`, and `.local.md`

Multi-tool repositories often accumulate rule files written for different workflows. Mizar scans the following filenames out of the box with no forced migration:

- **Committed shared rules**: `AGENTS.md`, `CLAUDE.md`
- **Personal local overrides (untracked in Git)**: `AGENTS.local.md`, `CLAUDE.local.md`

Within any directory, shared rules are loaded before `.local.md` overrides. At the global level, Mizar also checks `~/.agents/AGENTS.md` alongside `~/.mizar/AGENTS.md` so personal cross-project preferences stay easy to manage.

## Discovery & Proximity-First Eviction in Large Repositories

Suppose you launch Mizar inside `services/billing` within a large monorepo containing dozens of services:

```text title="Typical monorepo rule discovery path chain"
~/.mizar/AGENTS.md                   ← Global preferences (broadest personal rules)
~/.agents/AGENTS.md                  ← Global shared rules
repo/
├── .git/                            ← Stops ascending at repository root
├── AGENTS.md                        ← Repo-wide conventions
└── services/
    └── billing/                     ← Working directory at launch
        ├── AGENTS.md                ← Billing service conventions
        ├── AGENTS.local.md          ← Local debugging notes (untracked)
        └── migrations/
            └── AGENTS.md            ← Auto-loaded when read/edit touches migrations/
```

The complete lifecycle of rule discovery works as follows:

1. **Top-down ancestor chain**: At startup, Mizar walks upward from the working directory to find the project root marker (`.git` by default), then reads rules sequentially from `root → cwd`. Directories closer to your current code carry higher precedence.
2. **Dynamic subdirectory loading during work**: If the model later uses `read`, `write`, or `edit` on `services/billing/migrations/001.sql`, and `followSubdirs: true` (the default) is active, Mizar automatically loads `migrations/AGENTS.md` up to the remaining budget—no need to cram every module's rules into the opening prompt.
3. **Content fingerprint deduplication**: Within the global group and project group separately, Mizar hashes trimmed file contents so identical rules (for instance, symlinks or copied templates) never waste duplicate context.
4. **Oversized source file protection**: Any single rule file larger than **1 MiB** (`1,048,576` bytes, configurable via `instructions.maxSourceBytes`) is skipped with a warning so logs or doc dumps aren't accidentally injected as instructions.
5. **Proximity-first eviction above 64 KiB**: The combined instruction budget defaults to **65,536 bytes (64 KiB)**. When layered rules exceed the budget, Mizar **keeps rules closest to your current working directory and local overrides first**, dropping the broadest global and top-level ancestor files whole from the outside in. If only a single newest/nearest rule remains and still exceeds the budget, it is safely truncated from the tail at a UTF-8 character boundary.

## Quick Diagnostics with `/instructions`

Unsure whether the model saw a particular rule, or suspect an instruction file was truncated? Run this directly in the TUI input box:

```text title="Inspect loaded instructions in the TUI"
/instructions
```

This [slash command](/en/tui/commands/) lists every active rule file in effective order, its source tier, exact byte count, and whether any file was omitted or truncated due to deduplication, the per-file size cap, or the 64 KiB total budget. To run a clean diagnostic session with all directory instructions disabled, start with `--no-instructions`.

<Callout type="tip">

You can also customize `instructions.candidates`, `projectRootMarkers` (for example, adding `Cargo.toml`), or increase `maxBytes` in `.mizar/settings.json`. See [Configuration & Precedence](/en/config/).

</Callout>
