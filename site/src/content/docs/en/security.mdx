Mizar enforces runtime safety across two orthogonal axes: **workspace path scoping (`restrictToWorkspace`)** and an **interactive approval gate before non-read-only tools run (`--approve` / `/approval ask`)**.

<Callout type="warning" title="Default Posture Is Open for Local Speed">
  Out of the box, Mizar sets <code>restrictToWorkspace: false</code> and <code>ApprovalMode::Auto</code> so local workflows run without friction. Always enable at least one guard when exploring untrusted repositories or running risky batches.
</Callout>

## Axis 1: Workspace Path Scope (`restrictToWorkspace`)

Enabling `"restrictToWorkspace": true` in `settings.json` confines all built-in file tools (`read`, `write`, `edit`, `grep`, `find` in `mizar-tools-coding`, plus `read_file` / `list_dir` in `mizar-tool-fs`) to the workspace root:

- **Symlink Escape Defense (`resolve_canonical_target`)**: Canonicalizes paths down the tree — even for not-yet-created target files, by canonicalizing the nearest existing ancestor and validating remaining segments stay inside the canonical workspace root — backed by a **40-hop symlink loop guard**.
- **Shell Tool Caveat**: `restrictToWorkspace` **constrains file tools ONLY and does NOT sandbox `bash` subprocesses**. If `bash` remains enabled, commands can still touch paths outside the workspace via absolute paths or `../`.

## Axis 2: Interactive Approval Gate (`--approve` / `/approval ask`)

Implemented by `ApprovalGatePlugin` (`mizar-client`) on the `tools/pre-execute` waterfall:

- **Activation**: Pass `--approve` on launch, set `ui.approvalMode: "ask"`, or toggle interactively via `/approval ask` (`/approval auto` restores auto-run).
- **Gated Tools**: Read-only tools (`read`, `grep`, `find`, `list_dir`, `get_time`, `recall`) run without prompts. Every mutating or execution tool — **`write`, `edit`, `bash`, `codemode`, and mutating MCP tools** — requires approval (including nested mutating tool calls triggered inside `codemode`).
- **Four Approval Actions**:
  1. **Allow once**: Approve this single invocation.
  2. **Always allow tool**: Whitelist this tool name for the current session.
  3. **Deny**: Reject execution with a permission error.
  4. **Deny with reason**: Reject and feed your custom constraint message back to the model so it can revise its plan.

<Callout type="note" title="! / !! User Shell Commands Bypass the Gate">
  Commands typed directly by you using <code>!</code> or <code>!!</code> in the composer bypass <code>ApprovalGatePlugin</code> and tool allowlists.
</Callout>

## Defense-in-Depth Recipes

| Scenario | Recommended Flags / Config | Effective Guarantee |
| :--- | :--- | :--- |
| **Untrusted repo audit & edits** | `mizar --approve -C /path/to/repo` + `restrictToWorkspace: true` | File tools locked inside repo (symlink-safe); every `bash`/`write`/`edit`/`codemode` requires consent |
| **Read-only code review** | `mizar --read-only -C /path/to/repo` | Reduces coding tools to `read` / `grep` / `find` (+ `recall`) |
| **Code edits without shell access** | `"restrictToWorkspace": true, "excludeTools": ["bash"]` | Symlink-guarded file access with no OS command execution channel |
| **Block dangerous MCP subsets** | `"excludeTools": ["mcp__prod__*", "*_drop_*"]` | Matched tools become `Hidden` in both LLM schemas and `codemode` |
| **Ephemeral zero-trace run** | `mizar --isolated --no-persist -C /tmp/sandbox` | Ignores disk configs under `~/.mizar` and skips SQLite persistence |
