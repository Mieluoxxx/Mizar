To persist multiple model providers and switch between them anytime with [`/model`](/en/tui/commands/), create `~/.mizar/models.json` (or a project-level `.mizar/models.json`):

<CodeTabs tabs={providersTabs} />

The protocol field can be written as `api` or `protocol`, supporting three major wire formats:

- `openai-completions` (shorthand `completions`): Standard `/chat/completions` API, compatible with most third-party providers and local inference servers.
- `openai-responses` (shorthand `responses`; also supports `openai-codex-responses` / `azure-openai-responses`): OpenAI Responses streaming protocol.
- `anthropic-messages` (shorthand `anthropic` / `messages`): Anthropic `/v1/messages` protocol.

## Secure Credential References & System Keychain

**Never commit plaintext API keys to a repository.** Within `apiKey` and custom `headers` in `models.json`, Mizar supports dynamic credential resolution:

1. **Environment variable references**: Write `$VAR` or `${VAR}`, or specify `"apiKeyEnv": "MY_CUSTOM_KEY"`. `${VAR}` expansion is also supported in `baseUrl` (handy for switching corporate intranets or regional gateways).
2. **Dynamic command execution (recommended with the system keychain)**: When a value starts with `!`, Mizar executes the command via `sh -c` right before sending a model request and strips trailing newlines from stdout.

Here is a real-world setup storing your key in macOS Keychain with no plaintext secret on disk:

```bash title="Store your key in macOS Keychain"
security add-generic-password -a "$USER" -s "mizar-deepseek" -w "sk-your-key-here"
```

```json title="Read from the keychain on demand in ~/.mizar/models.json"
{
  "providers": {
    "deepseek": {
      "api": "openai-completions",
      "baseUrl": "https://api.deepseek.com/v1",
      "apiKey": "!security find-generic-password -a \"$USER\" -s mizar-deepseek -w",
      "models": [{ "id": "deepseek-chat" }]
    }
  }
}
```

If a credential or header value literally contains `$` or starts with `!`, escape it as follows:

- Write a literal `$` as `$$` (for example, `token-$$123` resolves to `token-$123`).
- Write a leading literal `!` as `$!` (for example, `$!literal` resolves to `!literal`).

<Callout type="warning" title="Missing environment variables are never sent verbatim">
  If a referenced environment variable is unset or empty, or if a <code>!command</code> exits with a non-zero status, Mizar reports a missing-credential error at request time and never sends an unexpanded <code>$VAR</code> string as a Bearer token.
</Callout>

## Direct Environment Connections & Overrides

For quick debugging, CI scripts, or switching test environments, environment variables can bypass or override file-based routing:

- **Direct connection (highest priority)**: Whenever `API_KEY` is set, Mizar constructs an active provider named `default` (regardless of whether `models.json` exists) using `PROTOCOL` (default `completions`), `BASE_URL`, and `MODEL`.
- **Partial overrides on existing config**: If `models.json` is already configured and `API_KEY` is unset, exporting `BASE_URL` or `MODEL` overrides only the endpoint or model ID of the active default provider without modifying files on disk.
- **Zero-config auto-detection**: When no `models.json` providers are configured, Mizar automatically checks `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, and `DEEPSEEK_API_KEY`, wiring up the matching protocol immediately if found.

```bash title="Temporarily switch gateways without a config file"
API_KEY="sk-test" PROTOCOL="anthropic" BASE_URL="https://proxy.internal" MODEL="claude-sonnet-4-5" mizar
```

## Connecting Local Ollama / vLLM

Most local inference servers expose an OpenAI Chat Completions–compatible endpoint without strict authentication:

```json title="Local Ollama / vLLM example"
{
  "providers": {
    "ollama": {
      "api": "openai-completions",
      "baseUrl": "http://127.0.0.1:11434/v1",
      "apiKey": "ollama",
      "compat": {
        "thinkingFormat": "qwen",
        "supportsUsageInStreaming": true
      },
      "models": [
        {
          "id": "qwen2.5-coder:32b",
          "name": "Qwen 2.5 Coder 32B",
          "reasoning": false,
          "contextWindow": 32768
        }
      ]
    }
  }
}
```

For private gateways that expect no auth header or a non-Bearer scheme, you can also set `"authHeader": false` or `"useBearerAuth": false` on the provider.

## Per-Model Tuning (`modelOverrides` & Effort-Level Sampling)

Repositories often want to inherit connection settings from a personal `~/.mizar/models.json` while overriding context windows or effort-specific sampling parameters for certain models. Add `modelOverrides` to your project `.mizar/models.json` to merge overrides by `models[].id`:

```json title="Match sampling parameters to reasoning effort levels"
{
  "providers": {
    "openai": {
      "modelOverrides": {
        "gpt-5": {
          "reasoningEfforts": ["low", "medium", "high"],
          "samplingParamsByThinkingLevel": {
            "low": { "temperature": 0.2, "maxTokens": 4096 },
            "high": { "temperature": 0.6, "maxTokens": 16384 }
          },
          "compat": {
            "maxTokensField": "maxCompletionTokens"
          }
        }
      }
    }
  }
}
```

Other common `compat` flags include `thinkingFormat` (`none` / `deepseek` / `openai` / `openrouter` / `qwen`), `forceAdaptiveThinking`, `sendSessionAffinityHeaders`, and `supportsMaxOutputTokens` to handle subtle differences across compatible gateways.
