Mizar 终端 AI 编程智能体

Mizar（mizar / mizar-tui）是基于自研 Cordis 插件微内核、纯 Rust 重写的全功能终端 AI 辅助编程工作台。 28 个 crate 模块化协同，集成了多提供方模型路由、AGENTS.md 层级热发现、QuickJS 沙箱代码编排、三泳道轨迹观测与 SQLite WAL 会话回溯能力。

单可执行文件，极速启动

纯 UI 渲染层（mizar-tui-ui）与异步宿主物理解耦，零外部 Node / Python 运行时依赖。

工作区隔离与工具审批

支持 restrictToWorkspace 文件防逃逸与 --approve 交互审批确认弹窗。

QuickJS + BM25 编排

把多步工具调用折叠到 rquickjs 沙箱内一次完成，中间海量输出不污染上下文。

层级指令动态热发现

自动沿 .git 祖先链加载 AGENTS.md / CLAUDE.md，超预算优先淘汰宽泛祖先。

一、30 秒极速上手路径

Mizar 提供三种渐进式启动方式，从零成本界面试玩到工程级多模型配置均可一键开启：

1. 无 Key 自动 Mock 试玩

当系统中既未配置环境变量密钥、也不存在 ~/.mizar/models.json 时，Mizar 自动挂载内置的离线假模型适配器 MockPlugin（模型 ID 为 mock-v1），按关键词模拟 get_time / list_dir 工具调用与流式输出：

Terminal · 离线演示模式 
# 直接启动，未检测到 API_KEY 时自动拉起 MockPlugin
mizar

# 在提示框中尝试输入：
# "项目里有哪些文件"  -> 模拟触发 list_dir 工具
# "搜索 Cargo"       -> 模拟调用搜索并逐字流式返回
# "/tools"           -> 查看当前已加载工具列表

2. 环境变量单模型直连

适合临时任务或无落盘环境。环境变量按 API_KEY（显式优先）或 OPENAI_API_KEY → ANTHROPIC_API_KEY → DEEPSEEK_API_KEY 顺序探测，并支持用 PROTOCOL / BASE_URL / MODEL 指定端点：

Bash · 环境变量直连 
# 方式 A：单 Provider 密钥环境变量直连
export DEEPSEEK_API_KEY="sk-xxxxxxxxxxxxxxxxxxxxxxxx"
export BASE_URL="https://api.deepseek.com/v1"
export MODEL="deepseek-chat"
mizar

# 方式 B：显式指定协议（completions 默认 / responses / messages）
export PROTOCOL="responses"
export BASE_URL="https://api.openai.com/v1"
export MODEL="gpt-5"
export API_KEY="sk-xxxxxxxxxxxxxxxxxxxxxxxx"
mizar

3. ~/.mizar/ 标准配置与从源码构建

推荐在个人目录初始化 ~/.mizar/，并使用 Rust 1.98.0（edition 2024）编译 mizar 二进制：

Bash · 构建与初始化 
# 1. 创建全局配置目录（可用 MIZAR_HOME 环境变量重定向）
mkdir -p ~/.mizar

# 2. 编译优化版终端入口 mizar
cargo build -p mizar-tui --release --bin mizar

# 3. 拷贝至 PATH 路径（或直接使用 cargo run -p mizar-tui --bin mizar）
cp target/release/mizar ~/.cargo/bin/mizar

二、配置分层与优先级体系

Mizar 按「全局配置 → 项目配置 → 环境变量 → CLI 启动参数」四级顺序装配，后级在同字段上覆盖前级：

1
全局配置目录：~/.mizar/（可由 MIZAR_HOME 覆盖）
存放跨项目共享的 settings.json、models.json、mcp.json 以及默认持久化库 sessions.sqlite。
2
工作区配置目录：<workspace>/.mizar/
按项目覆盖模型选择、工具策略；其中 models.json 按 Provider ID 插入覆盖，mcp.json 支持仅覆写暴露策略的 override-only 条目。
3
环境变量：API_KEY / PROTOCOL / BASE_URL / MODEL / WORKSPACE / MIZAR_SESSION_DB
当设置了显式 API_KEY（或无 models.json 但存在厂商密钥）时创建 default 路由；否则覆盖活动 Provider 的 baseUrl 与 model。
4
CLI 命令行参数：--workspace / --minimal / --tools / --exclude-tools / --approve
拥有最高运行时优先级；工具预设与白名单直接替换配置，但 --exclude-tools 同样按并集追加。
关键例外：excludeTools 与 skills.customDirs 为追加而非覆盖

根据 SettingsConfig::merge_overlay 源码实现，常规标量字段（如 defaultModel、toolsPreset、restrictToWorkspace）由项目级覆盖全局级。
但是 excludeTools（全局 + 项目 + CLI --exclude-tools）与 skills.customDirs（全局 + 项目）会逐项去重并集追加，不会清空上层配置！

核心环境变量一览

环境变量 作用说明
MIZAR_HOME重定向全局配置与默认 SQLite 根目录（默认 ~/.mizar）
MIZAR_SESSION_DB覆盖 SQLite 会话文件路径；设为 none / off / 空字符串时禁用自动落盘
MIZAR_AGENTS_HOME覆盖全局用户规则与技能目录根路径（默认 ~/.agents）
MIZAR_BUNDLED_SKILL_DIR指定内置技能包目录
WORKSPACE未传 --workspace/-C 时的默认工作目录
API_KEY / OPENAI_API_KEY / ANTHROPIC_API_KEY / DEEPSEEK_API_KEY模型请求密钥；API_KEY 优先级高于厂商专属变量
PROTOCOL / BASE_URL / MODEL覆盖直连协议（completions / responses / messages）、接口地址与模型名

三、三大配置文件详解：settings.json

settings.json 使用 strict JSON（不支持注释，兼容 UTF-8 BOM）与 camelCase 字段，全部字段均为可选：

字段名 (camelCase) 类型 默认值 作用说明
defaultProvider string null 默认提供方，对应 models.json 的 providers key
defaultModel string null 默认激活模型 ID
reasoningEffort string null 思考强度：off / minimal / low / medium / high / xhigh / max（别名 defaultThinkingLevel）
maxSteps number 不限 单轮工具步数上限；传 0 表示解除限制
persona string 内置中文助手人设 覆盖内置系统提示词开篇人设
toolsPreset string "all" 编码工具预设：all（6 工具）/ minimal（4 工具）/ read-only（3 工具）
tools string[] null 工具激活白名单（支持 * 通配）
excludeTools string[] [] 工具黑名单（支持 * 通配，跨级追加合并）
restrictToWorkspace boolean false 将文件工具（read/write/edit/grep/find）限制在工作区内部（bash 需配合 --approve）
sessionDb string ~/.mizar/sessions.sqlite SQLite 会话落盘路径（优先级低于 --no-persist 与 MIZAR_SESSION_DB）
codemode object — autoEnable (true)、onlyMode (false)、inlineBudget (3000)、timeoutMs (120000)
toolSearch object — autoEnable (true)、defaultLimit (8)
skills object — enabled (true)、customDirs (string[] 追加)、bundledDir、catalogDescriptionMaxLength (500)
instructions object — enabled (true)、candidates、localCandidates、projectRootMarkers、maxBytes (65536)、maxSourceBytes (1048576)、followSubdirs (true)

四、三大配置文件详解：models.json

models.json 采用 Pi 生态兼容的 providers 结构（同时兼容简化 protocol / apiKeyEnv 写法），支持按请求动态解析凭据与协议方言微调。

凭据动态解析与转义规则（$VAR / ${VAR} / !command）

• 环境变量展开："apiKey": "$DEEPSEEK_API_KEY" 或 "${CUSTOM_KEY}" 会在每次请求时动态读取，避免明文落盘。
• Shell 命令提取：以 ! 开头时（如 "!security find-generic-password -s mizar -w"）通过 sh -c 执行并裁剪末尾换行符。
• 字面量转义：$$ 转义为 $；\$! 或 $! 转义为字面量 !。未引用环境变量报错时返回 MissingCredential。

五、三大配置文件详解：mcp.json 与暴露控制

mcp.json 支持本地 stdio 子进程（command/args/env/cwd）与远程 Streamable HTTP（url/headers，自带 ${VAR} 环境变量展开）。 连接在后台异步进行不阻塞界面启动，所有工具命名空间统一规范为 mcp__<server>__<tool>。

exposure 等级 直接声明给模型 可被 codemode 调用 列入 codemode 描述 适用场景
"codemode"（默认） 否（需激活） 是 是 节省上下文首选：不把繁琐工具 Schema 塞入主对话，模型通过 JS 脚本直接调度
"deferred" 否（需激活） 是 否 海量工具库：由 tool_search（BM25）检索命中后才在下一轮激活声明
"direct" 是 是 — 高频核心工具：直接暴露给模型，无需经过脚本或检索中转
"hidden" 否 否 否 彻底屏蔽：禁用危险操作（例如结合 toolExposure 屏蔽删除工具）

通配符优先级：toolExposure 中精确工具名优先级最高，其次按含 * 通配规则的非通配字符长度（specificity）降序匹配。

实战配置示例（Tab 切换）

默认以 codemode 接入，并通过 toolExposure 通配精细放行 read_*、隐藏 delete_file：
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "${WORKSPACE}"],
      "exposure": "codemode",
      "toolExposure": {
        "delete_file": "hidden",
        "read_*": "direct"
      }
    }
  }
}
连接远程 Streamable HTTP MCP 服务端，headers 与 url 均支持 ${VAR} 变量替换：
{
  "mcpServers": {
    "remote-db": {
      "url": "https://mcp.internal.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${INTERNAL_MCP_TOKEN}",
        "X-Project-Id": "prod-core"
      },
      "exposure": "deferred",
      "timeoutMs": 15000
    }
  }
}
在 <workspace>/.mizar/mcp.json 中省略 command 与 url，即可局部修改全局 Server 的启用态或暴露级别：
{
  "mcpServers": {
    "remote-db": {
      "enabled": true,
      "exposure": "direct",
      "toolExposure": {
        "drop_*": "hidden"
      }
    }
  }
}

六、日常使用：CLI 启动参数速查

命令行参数 短参数 默认行为 详细用途与源码语义
--workspace <dir> -C <dir> WORKSPACE 或 cwd 显式指定工作区根目录
--minimal — 关闭 极简 4 工具编码预设（read / bash / edit / write）
--read-only — 关闭 只读 3 工具审计预设（read / grep / find）
--tools <a,b,...> -t 全量激活 逗号分隔的工具白名单
--exclude-tools <a,b,...> -xt [] 工具黑名单（支持 * 通配，与配置文件合并累加）
--inline — Fullscreen 模式 以 Inline 行内视口启动（保留终端原生滚动历史）
--approve — auto 免批 开启高危工具交互式审批闸门（ApprovalMode::Ask）
--continue -c 新会话 恢复当前工作区最近一次持久化的历史会话
--resume <id> -r <id> — 按会话 ID 恢复指定历史会话
--no-persist — SQLite 落盘 禁用 SQLite 会话落盘（仅当前进程内存模式）
--no-instructions — 自动发现 禁用自动发现与注入 AGENTS.md / CLAUDE.md
--theme <preset> — auto 指定预设主题：auto / mist-dark / mist-light / sakura-dark / system / ansi16

八、@ 文件引用与 #L 行范围切片

输入 @ 即时唤起模糊文件选择器（基于 ignore crate 索引，自动忽略 .gitignore 排除路径，索引缓存 TTL 5 秒，上限 8,192 条）：

模糊评分与带空格引号

支持子序列模糊匹配；若路径包含空格，上屏时自动格式化为 @"path with spaces/file.rs"。

目录连续下钻

选择目录候选后路径以 / 结尾且自动保留补全状态，可连续向深层子目录钻取。

#L 行范围精确切片

支持 @src/main.rs#L10-25 或单行 @src/lib.rs#L42，提交时仅切片目标行段注入 file-mentions 上下文。

中英文自然边界识别

识别中文标点（， 。 ：）、括号及反引号边界，混排输入中不会误识别。

十一、Skills 技能包与 QuickJS 沙箱编排

1. ~/.agents/skills 分层技能与 Rank 仲裁

mizar-skills 扫描技能根目录下的 <name>.md 或子目录 SKILL.md，解析 YAML frontmatter 并按 Rank 升序仲裁同名技能（数字越小优先级越高）：

  • 项目技能（Rank 200）：<workspace>/.agents/skills 与 <project_root>/.agents/skills
  • 自定义目录（Rank 300）：settings.json 的 skills.customDirs（跨级追加）
  • 用户全局（Rank 500）：~/.agents/skills（支持 MIZAR_AGENTS_HOME 覆盖）
  • 热失效：当 write / edit 修改命中技能目录时自动清缓存并广播 skills/change。

2. tool_search (BM25) + codemode (QuickJS 沙箱)

当系统存在 Codemode 或 Deferred 暴露等级的工具（如 MCP 服务）时，Mizar 自动激活两个高阶编排工具：

  • tool_search：基于 BM25 索引（工具名权重 4.0、命名空间权重 2.0，默认返回 8 条）按需检索并把匹配的 Deferred 工具激活到下一轮模型调用中。
  • codemode：内嵌 rquickjs 异步沙箱（内存上限 256 MiB，栈 1 MiB，默认超时 120s，并发信号量 max_workers: 2，内联目录预算 3,000 字符）。模型可在 JS 脚本内调用 searchTools()、describeTool() 及多个工具，将中间产物在沙箱内存消化，只返回最终汇总结果。

十二、SQLite WAL 会话持久化与 /tree 分叉回溯

  • Single-Writer 线程隔离：mizar-session-sqlite 开启 WAL 模式与 busy_timeout = 5000ms，通过独占后台线程批量提交事务，只读连接加 query_only，将磁盘 I/O 彻底隔离在 Tokio 异步调度器之外。
  • 断点续聊：正常退出终端时，若当前会话已持久化，控制台会自动输出可直接粘贴执行的 mizar --resume <id>（同工作区也可简写 mizar -c）。
  • /tree 时间线分叉：打开会话时间线树查看每条 USER / CTX / ASST / TOOL 事件序号，选中任意可分叉节点即可创建分叉新会话重新探索不同方案。

十三、安全模型与生产环境加固

安全默认值重要提示

为追求开箱即用的本地编程流利度，Mizar 的默认行为不设沙箱阻拦：
1. restrictToWorkspace 默认为 false：文件工具（read/write/edit/grep/find）可读写工作区之外路径。
2. approval_mode 默认为 auto：所有工具调用（含 bash 与写操作）均自动执行而不弹窗确认。

生产环境与敏感仓库推荐安全组合

在生产环境、不可信代码库或需要人工审计变更时，建议同时开启工作区路径限制与非只读工具交互审批（拦截全部非 read_only 工具，支持单次放行、本工具始终放行、拒绝或附理由拒绝）：

十四、高频问题排障 FAQ

Q1：启动后顶部提示「未检测到 API_KEY 或 ~/.mizar/models.json，当前使用离线假模型」？
当 Mizar 未在环境变量找到 API_KEY / OPENAI_API_KEY / ANTHROPIC_API_KEY / DEEPSEEK_API_KEY，且全局/项目 models.json 为空时，会自动回退至离线 MockPlugin（mock-v1）。
排查：确认目标环境变量已在当前 shell export 且非空，或检查 ~/.mizar/models.json（注意 JSON 内不可写 // 注释，否则启动通知栏会报「配置解析失败」）。
Q2：为什么配置了 MCP Server，但在模型工具列表或 /tools 中看不到全部工具？
Mizar 对 MCP Server 默认使用 "exposure": "codemode"，这会让工具对模型主循环保持隐藏，改为通过 codemode JS 沙箱或 tool_search 按需调度以节省大量上下文 Token。
解决：在 mcp.json 将该服务或特定工具的 toolExposure 设为 "direct"；若仍不可见，检查是否被全局或项目级 excludeTools（追加合并）屏蔽。
Q3：为什么在全局或项目配置文件里写了 // 注释导致配置没生效？
settings.json、models.json、mcp.json 均由 Rust serde_json::from_str 严格解析（仅自动剥离 UTF-8 BOM），不接受 JSONC 注释或尾随逗号。如解析报错，启动时会在通知栏打印具体文件名与行号。
Q4：如何临时使用终端软件自带的划词选中与复制？
Mizar 默认启用应用级鼠标追踪以支持双栏分栏精确划词（松手自动复制）。按 F2 或输入 /mouse 即可放行系统终端原生选区，再次按下即可恢复。
Q5：在只读磁盘、容器或无 ~/.mizar 写权限环境中如何运行？
使用 mizar --no-persist 启动，或设置环境变量 export MIZAR_SESSION_DB=none，即可完全跳过 SQLite 数据库初始化，在纯内存中完成会话。
Q6：AGENTS.md 修改后未完整注入或部分较早祖先规则消失？
mizar-instructions 默认单文件上限为 1 MiB、总注入预算为 65,536 字节。超预算时按「优先淘汰最宽泛祖先、保住最贴近当前目录规则」原则裁剪。请在会话内运行 /instructions 检查每个作用域的字节与裁剪状态。
